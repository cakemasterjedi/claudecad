# ScriptForge capabilities

Current state of the prompt → Onshape builder and the local builder. The feature table is generated by
`scriptforge features --markdown` from `scriptforge/native/catalog.json` and the local builder; regenerate it after
new features get learned.

## New-part workflow: what runs locally, what costs Onshape API calls

| step | where | Onshape calls |
|---|---|---|
| LLM writes the Part Studio script | Claude (CLI or API) | 0 |
| syntax, units, feature/parameter/enum check | local tracer | 0 |
| geometry build, volume, hole sizes, render | local builder (OpenCascade) | 0 |
| print check: overhangs flatter than 45° that are not on the bed | local (`scriptforge studio check/build`) | 0 |
| geometry check: valid B-rep, closed shell, positive volume, one solid, watertight STL mesh, per part | local (`scriptforge studio check/build`) | 0 |
| wall check: regions thinner than `--min-wall` (default 1.2 mm) by ray casting | local (`scriptforge studio check/build`) | 0 |
| per-part STEP/STL and 3MF (one object per part) | local (`scriptforge studio build --formats step,stl,3mf`) | 0 |
| fit check: parts in their assembled position, real components (STEP), hinge/slide motions | local (`scriptforge studio fit`) | 0 |
| cross-section PNG of the assembly (`[section]` plane in the fit file) | local (`scriptforge studio fit`) | 0 |
| interactive 3D viewer (print layout, assembly, exploded) | local HTML (`scriptforge studio view`) | 0 |
| repairs from script/local errors | local loop | 0 |
| review (model looks at the local 4-view render) | local loop | 0 |
| cost estimate before pushing (shown as calls and % of what's left) | local, from the feature diff | 0 |
| create Part Studio | Onshape | 1 |
| variables (one Variable Studio, any number) | Onshape | 3 first time, then 1 per change |
| each feature (sketch, extrude, fillet, …) | Onshape | 1 |
| sketch on a part face: measure Onshape's axes on the face | Onshape | +1 per face sketch sent |
| feature fails in Onshape → diagnosis | Onshape | 1 (fix = 1 in-place update) |
| confirm Onshape volume = local volume | Onshape | 1 |
| Onshape render (only if local result was partial or differs) | Onshape | 0–1 |
| local STEP/STL/PNG, copy to Dropbox | local | 0 |
| STEP/STL export via the API (opt-in `--export`) | Onshape | STEP ~4, STL 1 (the Onshape UI exports for free) |
| editing a dimension later and re-pushing | Onshape | 1 per changed feature (+1 status check); unchanged = 0 |
| changing a variable in Onshape's Variable Studio by hand | Onshape UI | 0 (sketches follow their dimensions) |
| STEP → editable script (`scriptforge recognize`) | local (featuretree) | 0 (push = features + 2) |
| paste version (custom feature, `scriptforge studio paste` / `generate --paste`) | you paste it in the Onshape UI | **0** |

Before every push, `generate` and `scriptforge studio check|build|push` print e.g.
`estimated Onshape API calls: 13 (new Part Studio 1, Variable Studio 3, features 9) = 0.7% of the calls left`.
`--budget N` refuses to push above N. The estimate equals the real count (tested against a fake Onshape).

Typical cost: a 9-feature part with 5 variables = 14 calls (measured: pillow block). Rule of thumb:
**features + 5** for a new part, **1–2** for an edit.

## Features

| feature (Onshape type) | status in Onshape | local builder | notes |
|---|---|---|---|
| Variable (`assignVariable`) | verified | yes (values used directly) | variable(context, name, value): by default all variables go into one Variable Studio (3 calls total); SCRIPTFORGE_VARIABLES=tree makes Variable features in the tree (1 call each). |
| Plane (`cPlane`) | verified | OFFSET only | Offset plane: entities = a plane/face, offset = distance (cplaneType is sent automatically). |
| Chamfer (`chamfer`) | verified | EQUAL_OFFSETS only | chamferType ChamferType.EQUAL_OFFSETS + width. |
| Circular pattern (`circularPattern`) | verified | FEATURE and PART; equal spacing / fixed angle | patternType FEATURE + instanceFunction [feature ids]; axis can be a construction line. ScriptForge sends fullFeaturePattern (Reapply features) by default. |
| Extrude (`extrude`) | verified | NEW/ADD/REMOVE/INTERSECT; BLIND, THROUGH_ALL, symmetric, second direction; no UP_TO_*, draft | A REMOVE extrude pointing away from the part finishes with INFO and cuts nothing; check the sketch normal. |
| Fillet (`fillet`) | verified | constant radius (OCCT may fail where Onshape succeeds -> warning) | Select edges geometrically: qParallelEdges(edges, vector), qContainsPoint(edges, point on edge). |
| Mirror (`mirror`) | verified | FEATURE and PART | patternType FEATURE + instanceFunction; mirrorPlane = a default plane face. |
| Sketch (`newSketch`) | verified | lines, arcs, circles, rectangles, polylines, polygons; Top/Front/Right, offset planes, planar faces* | Constraints and dimensions are generated automatically: rectangles, circles and every line/polyline/arc vertex, dimensioned to the (projected) origin, so Variable Studio edits move them (verified 2026-10-10 on default planes, offset planes and part faces). |
| Revolve (`revolve`) | verified | full or angle, symmetric, opposite direction | Axis: a construction line in the profile sketch via sketchEntityQuery(id + "Sketch", EntityType.EDGE, "axis"). |
| Shell (`shell`) | verified | faces to remove, inward (or opposite direction) | Positive thickness hollows inward; entities = faces to remove. |
| Linear pattern (`linearPattern`) | learned | FEATURE (extrude/revolve/loft) and PART; one or two directions |  |
| Loft (`loft`) | learned | solid between sheet profiles (outer wires); no guides/conditions |  |
| Boolean (`booleanBodies`) | available | UNION / SUBTRACTION / INTERSECTION, keepTools |  |
| Delete part (`deleteBodies`) | available | yes |  |
| Helix (`helix`) | available | axisType CIRCLE (sketch circle) or AXIS; TURNS / PITCH / TURNS_PITCH, handedness; no SURFACE, end point |  |
| Sweep (`sweep`) | available | solid NEW/ADD/REMOVE/INTERSECT along edges (helix: exact screw motion); no profile control, twist, scale |  |

\* on a part face, script coordinates start at the world origin projected onto the face, with the axes of the
parallel default plane (y = normal × x). Onshape's sketch there has the same origin but the face's own x-axis, which
depends on how the face was made, so the push measures it (1 call per face sketch sent) and turns the sketch.
Pick faces by feature (`qCapEntity`, `qNonCapEntity` + `qParallelPlanes`), not by point: point queries are fixed
numbers in Onshape and lose the face when a variable moves it. Example: `examples/native/face_sketches.fs`.

## Local builder (`scriptforge/native/local.py`)

Runs Part Studio scripts offline (0.1–0.4 s per part) on the FS-Lite OpenCascade layer that was
checked against Onshape in `examples/compat` (11 parts, identical volume/area).

Accuracy against Onshape (`tests/test_native_local.py`):

| part | Onshape volume (mm³) | local | difference |
|---|---|---|---|
| plate (sketch, cut, 2 mirrors, fillets) | 23244.385 | 23244.385 | 0 |
| L-bracket (profile, symmetric extrude, holes, fillet) | 24858.988 | 24858.988 | 0 |
| flange (revolve, circular pattern, chamfer) | 32356.310 | 32356.310 | 0 |
| enclosure (shell, offset plane, bosses, side hole) | 30000.836 | 30000.836 | 0 |
| NEMA 17 mount (LLM-generated, 23 features) | 19831.865 | 19831.865 | 0 |
| fan adapter (LLM-generated, loft, linear pattern) | 43299.793 | 43299.838 | +0.0001 % |
| pillow block (LLM-generated) | 34408.184 | 34408.184 | 0 |
| face sketches (sketches on 3 part faces, cuts) | 6932.246 | 6932.246 | 0 (also after a Variable Studio edit) |

Threads (helix + sweep) are not yet measured in Onshape. Locally they are checked against exact values instead:
a profile swept along a helix is a screw motion, so its volume is area × centroid radius × swept angle (local
result within 1e-5 for 0.5–10 turns), and the M12x2 bolt and nut (`examples/native/m12_bolt_nut.fs`) screw
together: no shared volume at any position along the right-handed thread path, ~75 mm³ when half a pitch out
of phase or turned left-handed, 0.1 mm flank gap with 0.2 mm radial clearance.

What it does:
- sketches: lines, arcs, circles, rectangles, polylines, regular polygons, construction geometry, regions
  (incl. "drop inner loops"); default planes with Onshape's axis conventions, offset planes, planar faces
  (ScriptForge's face frame, see above)
- extrude, revolve, loft, fillet, chamfer (equal), shell, offset plane, booleans, delete
- threads: helix (on a sketch circle or around an axis; turns/pitch/height, handedness) and solid sweep along
  any connected edges (helix: Frenet frame = exact screw motion; other paths: corrected Frenet)
- feature patterns (linear, circular, mirror; also patterns of patterns) and part patterns
- queries: the FeatureScript query functions used by scripts (qCreatedBy with provenance through booleans and
  fillets, qSketchRegion, sketchEntityQuery, qParallelEdges, qContainsPoint, qCoincidesWithPlane, qGeometry,
  qLargest, qFarthestAlong, qCapEntity, qNonCapEntity, qParallelPlanes, …)
- Onshape behaviours: REMOVE that cuts nothing → warning (Onshape INFO); empty selections → error (Onshape
  ERROR); kernel-only failures → warning, not a false error
- sketch edges and the part's edges are separate entities (an extrude's end face reuses the sketch's edges)
- fillets/chamfers that OCCT refuses at meter scale are retried at millimeter scale (history kept)

Not yet: UP_TO_* bounds, draft/taper, helix on a cylinder face (axisType SURFACE) or to an end point, sweep
profile control/twist/scale, thicken, hole, sheet metal, surfaces, splines/ellipses in scripts, sketch
constraints (dimensions only matter in Onshape), Onshape assemblies (multi-part fits are checked locally with
`scriptforge studio fit` instead).

## Multi-part designs: fit check and viewer (`scriptforge/native/fit.py`, `viewer.py`, `printcheck.py`)

Printed parts are laid out in print orientation, so the preview alone cannot show whether they fit together.
A fit file next to the script (`parts/<name>.fit.toml`) moves each part from the print layout into its assembled
position (picked by a point inside it; move/rotate/rotation-matrix steps; mirrors are rejected because a printed
part cannot be mirrored), adds components (the real thing as a STEP file, wires and pins as cylinders or boxes)
and lists motions. `scriptforge studio fit` reports the overlap of every pair when assembled and, for each motion, the
overlap at each step: `free`, `snap` (small overlap near the closed position, gone later), `blocked` (still
overlapping at the last step) or `collides`. An `expect` per motion turns it into a pass/fail check. Example:
`examples/native/fit/lidded_box.fs` + `.fit.toml`. On a 7-part current clamp (hinge, latch, sleeves, covers,
liner, the ferrite STEP, pin and wire) the check takes ~7 s.

`scriptforge studio fit` also writes `out/<name>/<name>_section.png`: every part and component in the assembled position
cut by the plane of the fit file's `[section]` table (`origin`, `normal`; default the XZ plane), drawn as filled 2D
areas, one colour per part. `scriptforge studio view` adds an "Exploded" scene: parts spread along `[view] explode`
(default Z) by `explode_distance` (default 20 mm) times their rank along it.

## Geometry checks and exports (`scriptforge/native/geomcheck.py`, `partexport.py`, `section.py`)

`studio check|build` print, after the print check, one line per part: `geometry check: part 1 ok (valid B-rep,
closed, watertight mesh, 1 solid)` or the problems (invalid B-rep, open edges, no volume, several solids, mesh edges
not shared by exactly 2 triangles). Then the wall check: wall thickness is the distance along the inward normal to
the first exit through the surface, from up to 4000 random surface points per part (numpy ray casting on a 0.05 mm
mesh, ~0.6 s for a 36-face enclosure); thin points are grouped into regions (min thickness, area, location in
mm). Rays that leave at a grazing angle are dropped, so fillets and chamfers do not show up as thin; features
smaller than the ~1 mm sample spacing can be missed, and fine threads report their crests. `--min-wall MM`
changes the limit.

`studio build --formats step,stl,3mf` (default `step,stl`): the combined `<name>.step/.stl` as before; `3mf` adds
`<name>.3mf` with one named object per part (mm). With more than one part, each part is also written as
`<name>_<part>.<ext>` in its print layout position; part names come from the fit file (`[parts.<name>]`), else
`part<N>`.

Part names and colors (multicolor printing): `setProperty(context, { "entities" : q, "propertyType" :
PropertyType.NAME, "value" : "Yellow" })` and `PropertyType.APPEARANCE` with `"value" : color(r, g, b)` (components
0..1, as in Onshape) are stored on the bodies, kept through later booleans/extrudes/fillets of those bodies, and
applied by the local build in script order (they are not features: `studio paste` writes them into the pasted custom feature, as std `setProperty`/`color` calls at their place in the feature order; the REST `studio push` cannot send them and warns "part names and colors are not pushed by REST push" in the estimate, the push result and the web push). Other
property types log a warning and are ignored. Export: the setProperty name comes first, the fit file overrides it by
`at` point, else `part<N>`. Solids that share a name are ONE group: one 3MF object (a compound mesh, labelled with the
name, colored by the appearance) and one `<name>_<group>.<ext>` per group; with no names set nothing changes. The
preview PNG shades bodies in their appearance color.
Overlap check (multicolor builds: more than one solid and at least one name set): `studio check|build` and the web
check list pairs of solids whose volumes overlap by more than 0.001 mm3 (bounding-box prefilter, then
`fit.overlap`); touching is fine. It only reports, export is not blocked. The prompts (`scriptforge spec`) have a short
"Multicolor parts" section: one NEW body per color, no overlaps, name + `color(r, g, b)` (0..1) on every body.
Example: `examples/native/multicolor_tag.fs` (base + disc + bar, three 3MF objects). See `parts/champ_ring_logos/make_ring.py` (Bambu AMS ring).

## Multicolor emboss library (`scriptforge/native/colorlayers.py`, `emboss.py`)

Raised flat-color art on a base part, as a library (plain functions; shapely + stdlib only at import, `svgelements`
is imported lazily by `from_svg`). 2D side (`colorlayers`, mm, +y up): `Layer(color, name, geometry, height, label)`;
`split(layers)` (top priority first: each layer loses everything above it, hairline slivers closed/opened by 0.03 mm,
pieces under 0.01 mm2 dropped); `widen(layers, min_width=0.45, carve=False, absorb=True, absorbed=None)` grows thin bands (opening of radius
min_width/2 removes them; pieces under 0.5 min_width2 or shorter than 1.5 min_width are tips/specks and left alone)
over lower layers or empty space, never over a higher layer, re-cleans the lower layers and returns `(layers, still
thin)`; `carve=True` also lets a band enclosed by higher layers take area from them, only when that lowers the
total thin score; `absorb` (default) merges a band still thin afterwards into the adjacent higher layer with the longest shared border (that layer gets slightly wider there; each merge is appended to `absorbed` as (from, to, label, area)); `Emboss` simplifies each placement's layers by 0.01 mm with lower layers losing the simplified higher ones, so solids never overlap; `thin_report`, `narrowest`; `from_svg(path, height=, names=)` (filled paths/rects/circles, painter
order, fill rules, viewBox/transform, text and stroke-only shapes ignored with a warning, colors named from a small
table); `fit(layers, width, center, mirror_u)`, `mirror`, `translate`. FeatureScript side: `Emboss(base=<FS query of
the base bodies>)` with `flat(name, plane, layers)` (each layer NEW from the sketch plane by its height, then
base subtracted with keepTools) and `cylinder(name, plane, layers, standoff, depth_in, opposite, axis_plane,
axis_center, radius, span)` (prisms from `standoff` outside the barrel, trimmed per height by an INTERSECT extrude of
a circle of radius + height scoped to those prisms, base subtracted), `properties(base=(name, hex))` (one NAME +
APPEARANCE per color group), `source()`. Only std calls already used in `parts/*.fs` (newSketch, skPolyline,
skCircle, extrude, booleanBodies, setProperty, color). The INTERSECT trim reproduces the former crescent REMOVE trim
exactly (same volumes on the ring). Used by `parts/champ_ring_logos/make_ring.py`; tests: `tests/test_colorlayers.py`,
`tests/test_emboss.py`.


### `scriptforge emboss ART.svg PART.fs` (0 Onshape calls)

Puts a flat-color SVG on an existing native script as raised multicolor bodies (uses the library above). PART.fs is
not overwritten: the output is `<stem>_emboss.fs` unless `-o`. The block is appended at the end of the `build`
function (`export function build(context is Context, id is Id)`, or the function inside `defineFeature`). Base query:
`qSubtraction(qAllModifiableSolidBodies(), qUnion([<art extrudes>]))`, i.e. everything that is not art, evaluated lazily
(works however the file made its bodies; accepted by fslite, the tracer, paste and Onshape). Feature ids and sketch
variables are made unique, so it can be run again on its own output (second art gets `Emboss 2 ...`).

    scriptforge emboss logo.svg examples/native/multicolor_tag.fs --plane top --offset 3 --width 5.6 --center -1,0 \
        --skip-color '#ffffff' --heights Yellow=0.8 --names '#f5d90a=Gold'
    scriptforge emboss logo.svg barrel.fs --cylinder 20 --plane right --offset 20 --center 0,15 --width 16   # curved face
    scriptforge studio build examples/native/multicolor_tag_emboss.fs --formats step,stl,3mf

Art (u, v) = the plane's sketch x, y seen from its normal side (Top u=X v=Y, Front u=X v=Z, Right u=Y v=Z); `--flip`
extrudes against the normal, `--mirror` mirrors u. With `--cylinder R`, `--offset` is the signed distance of the barrel's
apex line from the plane (negative = the -normal side), `--axis-plane` is the default plane perpendicular to the axis,
`--axis-center U,V` the axis position, `--standoff/--depth-in/--span/--span-side` as in `Emboss.cylinder`. The report
lists color groups, widening (before/after, absorbed, still thin) and the placement box.

## Two ways to get a part into Onshape

| | paste a custom feature (`--paste`) | push a native tree (default) |
|---|---|---|
| API calls | 0 (you paste in the UI) | ≈ features + 5 |
| in Onshape | one feature with a parameter dialog | separate Sketch/Extrude/Fillet features |
| editing | change parameters in the dialog | edit any sketch, dimension or feature |
| checked before Onshape | yes (custom feature = native build, locally); confirmed working in Onshape | yes, plus 1-call volume check in Onshape |

`generate` always writes `paste_feature.fs` next to the script, so you can choose per part.
`scriptforge studio paste script.fs` writes it, copies it to Dropbox and the clipboard.

## STEP → editable Onshape tree (featuretree)

`scriptforge recognize part.step` uses [featuretree](https://github.com/punkfab/featuretree)'s feature recognition
(MIT, vendored in `third_party/featuretree`) and translates its result into a Part Studio script, checked with
the local builder. The translation is exact (same volume as featuretree's own rebuild on every test part); the
recognition is the limit: prismatic parts with through holes are recovered fully, while fillets, chamfers,
shells, bosses and revolved shapes come back PARTIAL. On our test parts: plate exact; L-bracket, pillow block,
enclosure and flange partial. The command only suggests a push when the volume matches the STEP. Recognized
parts can come back re-oriented (featuretree turns the extrude axis onto Z).

## Other tools on this machine

- **FreeCAD**: `scriptforge studio build file.fs --open` opens the local STEP in FreeCAD. featuretree can also emit
  editable FreeCAD trees from its IR (`third_party/featuretree/fc_build.py`); not wired into scriptforge.
- **OpenSCAD**: not used. It is mesh/CSG based (no B-rep, no feature tree), so it adds nothing here.
- **Dropbox** (`SCRIPTFORGE_DROPBOX_DIR`): `generate` and `studio build --dropbox` copy the script, local STEP/STL
  and render to `Dropbox/scriptforge/<part>/`, where Onshape's Dropbox integration can import them (free in the UI).
  Onshape can also translate straight to Dropbox (`cloudStorageAccountId` in the translation API), but the
  local STEP is free and matches Onshape, so this is not used.

## Onshape FeatureScript MCP server (Onshape Labs)

An MCP server is a standard way for Claude to use external tools. Onshape's FeatureScript MCP server lets
Claude write FeatureScript into a Feature Studio, run it and read errors. It logs in with your Onshape account
(OAuth) and, as Onshape notes, normal API limits apply. It only makes custom features (Feature Studio code), not
Sketch/Extrude feature trees, so it cannot replace the native pipeline. It could be useful for FeatureScript
documentation lookups and for developing custom features. To connect it to Claude Code (interactive login):

```
claude mcp add --transport http onshape-featurescript https://fs-mcp.labs.onshape.app/mcp
```
then run `/mcp` in an interactive Claude Code session to log in.
